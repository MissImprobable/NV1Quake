# nv1Quake installers - design

Date: 2026-10-03. Status: awaiting review.

## Goal

Three installers, one per build, generated by a single repeatable script, and
published together on one NV1 Quake product page on abnormalitysoftware.com.
They must carry everything id Software's licence documents require, and use the
Fragged logo throughout.

| Variant | Build | Installer technology |
|---|---|---|
| Emulated | `nv1quake.exe` (software NV1, Windows 10/11) | Inno Setup |
| Win95 | `nv1q95.exe` (real NV1, Windows 95) | Fragged `retro-installers` engine (Win32, MinGW, no CRT) |
| DOS | `nv1qdos.exe` (real NV1, DOS4GW) | Fragged `dos-installers` engine (real-mode MZ, Open Watcom) |

## Decisions already made (with the user)

- **Engine only.** No `id1\` content in any installer. The user supplies their
  own `PAK0.PAK` / `PAK1.PAK`.
- **Fragged logo everywhere:** installer icon, uninstaller icon, shortcut icons,
  Inno wizard art, and embedded in the game executables themselves.
- **Vendor the two Fragged engines** into this repo and extend them; the Fragged
  repo is not modified.
- **Build and publish all three** to a single product page. The user has no
  product art yet; placeholder art now, replaced later.
- The Win95/DOS licensing uncertainties below are accepted and stated in
  `NOTICE.TXT`.

## Layout

```
NV1Quake/installers/
  build-installers.ps1     entry point (see below)
  publish-to-site.ps1      R2 upload + versions.json + product page, push
  VERSION                  single source of the version number (0.10)
  legal/
    COPYING.TXT            id's gnu.txt, unmodified
    NOTICE.TXT.in          template; version/commit/URL filled at build time
    README-ENGINE.TXT.in   "you must supply your own Quake data" text
  art/                     copies of the Fragged assets (see Branding)
  inno/NV1Quake-Emulated.iss
  retro/                   vendored Win32 engine + packer + win95 main.c + .rc
  dos/                     vendored DOS engine + packer + dos main.c
  stage/                   generated: files per variant (gitignored)
  output/                  generated: installers, SHA256SUMS, source zip (gitignored)
```

## build-installers.ps1

`build-installers.ps1 [-Variant emulated|win95|dos|all] [-Rebuild] [-Version x.y]`

1. **`-Rebuild`**: runs `build.bat`, `build-nv1.bat`, `build-dos.bat` from
   `NV1Quake\`, so installers are never built from stale binaries (the Win95
   binary in `Release\` is currently stale). Fails loudly if a build fails or an
   expected exe is missing.
2. **Stage** each variant into `stage\<variant>\` from the freshly built output:
   exe, README, plus `NVVIDMOD.DLL` (Win95) or `DOS4GW.EXE` (DOS). The script
   asserts that no `*.PAK` or `id1\` exists in any stage and aborts if one does.
3. **Legal files** added to every stage: `COPYING.TXT`, `NOTICE.TXT` (rendered
   from the template with version, git commit, source URL), `README.TXT`.
4. **Build** each installer into `output\`:
   - emulated: `ISCC.exe /DAppVersion=... NV1Quake-Emulated.iss`
   - win95: compile engine + game `main.c` + `.rc` (MinGW `i686-w64-mingw32-gcc`,
     the same flags as `FraggedLANManager\retro-client\Makefile`), run the packer
     to embed the stage, link
   - dos: `wcc -bt=dos -ml`, link a DOS MZ stub, run the DOS packer
5. **Source offer:** `git archive` of the exact commit to
   `NV1Quake-<ver>-source.zip`, plus `SHA256SUMS.txt` over everything.

Tool paths default to the existing conventions (Inno `C:\Program Files\Inno
Setup 7`, Watcom `C:\WATCOM`, MinGW as already installed) and are parameters.
Each variant can be built alone, so adding or redoing one later does not need
the others.

## Branding

Assets come from `X:\repos\FraggedLANManager` and are copied into `art\`:

| Use | Asset |
|---|---|
| Inno setup + uninstall icon, shortcuts | `installer\app.ico` |
| Inno wizard art | `installer\GameInstallers\fragged-wizard.bmp` (164x314), `fragged-wizard-small.bmp` (55x58) |
| Win95 installer, uninstaller, shortcuts | `retro-client\installer\retro-app-small.ico` (16+32 px only; Win95 cannot render the 256 px frames in `app.ico`) |
| DOS installer | the logo splash already drawn from `dos-installers\engine\logo.h` (DOS executables cannot carry icons) |
| Game exes | the same `app.ico` / `retro-app-small.ico` embedded via a new `.rc`: `nv1quake.exe` (MSVC `rc`) and `nv1q95.exe` (Watcom `wrc`). `nv1qdos.exe` is DOS and cannot carry an icon. |

Embedding the icon in the game exes means a small change to `build.bat` and
`build-nv1.bat` (add the compiled resource to the link). Product art for the web
page is a placeholder (Fragged logo on a plain panel) until real art exists.

## Licensing: what each installer must carry

From id's own documents in this repo (`readme.txt`, `WinQuake\data\LICINFO.TXT`,
`SLICNSE.TXT`, `RLICNSE.TXT`):

1. **GPL.** id's readme: if you distribute new binaries "you are required to make
   the entire source code available for free to everyone." Every installer
   installs `COPYING.TXT` (gnu.txt) and `NOTICE.TXT`; the notice states that the
   program is derived from id's 1999 GPL release, summarises the modifications
   (new renderer/port; id's code unmodified), and names the source repository
   and exact commit. The source zip is published next to the installers, which
   also serves as the written offer.
2. **No game data.** id's readme: "you cannot redistribute data from the original
   game." No installer contains PAK files. `README.TXT` tells the user to supply
   `PAK0.PAK` (and `PAK1.PAK` for the registered game) from their own copy.
3. **Non-commercial, no id branding** (LICINFO: no commercial exploitation, no
   use of id's names/logos/graphics for the shareware or registered games).
   Installers are free, and contain no id logos or Quake art. `NOTICE.TXT`
   says the port is unofficial and not endorsed by id Software or NVIDIA.
4. **Credit line** on every installer: "Installer created by Abigail /
   Abnormality Software (2026)", as on the other retro installers.
5. **NVIDIA.** `NVVIDMOD.DLL` ships with the Win95 build: NVIDIA's SDK overview
   says it "must be shipped with the NV-direct application" and it lives in the
   SDK's `REDIST` folder.

### Open licensing risks (accepted, stated in NOTICE.TXT)

- `nv1q95.exe` / `nv1qdos.exe` statically link NVIDIA's `nvlib.lib`,
  `nvlibdos.lib` and `nvrm.lib` into GPL-derived code. The SDK contains no
  licence text, so it is unverified that this combination may be redistributed.
  The emulated build is not affected (it links `nvsoft`).
- `DOS4GW.EXE` is bundled from Open Watcom. No redistribution grant for it was
  found in the local Open Watcom documentation.
- The name "Quake" in the product name: acceptable for a free, non-commercial,
  clearly unofficial port per LICINFO; flagged in case that changes.

This is engineering notes, not legal advice.

## Engine changes (vendored copies)

Neither Fragged engine can show a licence. Each gets one new "Licence and
notices" screen shown before extraction (scrollable text of `NOTICE.TXT`, press
to continue; GPL does not require acceptance, so it is informational) and
both install `COPYING.TXT`, `NOTICE.TXT` and `README.TXT` into the install
directory. The retro engine's `GameProfile` points `shortcutIconRelative` at the
installed `.ico`. Nothing else in the engines changes.

## Emulated installer (Inno)

DiskPixie-style script: `AppId` GUID, `LicenseFile=COPYING.TXT`, an info page
with `NOTICE.TXT`, wizard art and `SetupIconFile` from `art\`, `{autopf}`
install, Start Menu and optional desktop shortcut, `UninstallDisplayIcon` set to
the installed `.ico`. A custom wizard page asks for the user's own Quake `id1`
folder and copies `PAK0.PAK`/`PAK1.PAK` into `{app}\id1`; it may be skipped.
Passes the credit line via `AppCopyright`.

## Publishing (publish-to-site.ps1)

Follows the existing site pattern (R2 bucket `abnormalitysoftware-downloads`,
`/dl/` counted downloads, `versions.json`), with one product page for NV1 Quake
offering three downloads (Windows 10/11, Windows 95, DOS) plus the source zip.

- Uploads to `NV1Quake/<file>` via `wrangler r2 object put ... --remote`.
- Adds an `nv1quake` entry to `versions.json` (`version` + `url`, pointing at
  the emulated installer) and creates `apps/nv1quake.html`.
- Stages **only its own files** in the site repo (explicit paths, never
  `git add -A`): the site repo currently has unrelated uncommitted changes.
- **Publishing is a separate, explicit step.** The script defaults to a dry run
  that prints what it would upload and change; `-Publish` performs it.

## Verification

- Emulated: install silently and interactively into a scratch dir, confirm files,
  shortcuts, uninstall, and that the id1 copy page works with and without data.
- DOS: run the installer in DOSBox with a scripted run, confirm the extracted
  tree and that `NV1QUAKE.EXE` starts (past the pak check, per `ISSUES.md`).
- Win95: build and inspect (PE subsystem 4.0, no imports newer than Win95,
  icon resource present). It cannot be run here; it needs a Win95 VM or real
  machine, and the user's 86Box VM is the obvious place.
- Every stage: automated assertion that no `*.PAK` / `id1\` is packaged.
- Neither hardware build has run on a real NV1; the product page says so.

## Out of scope

Real product art (placeholder now), code signing, auto-update wiring beyond the
`versions.json` entry, and any change to the engine/renderer code.
